# Logowanie kodem

`import { SignInForm } from "@koperty/ui/views/account/sign-in-form";`

## 1. Do czego służy

Loguje bez hasła w dwóch krokach: adres e-mail, potem 6-cyfrowy kod z wiadomości (S-01). Link z tej samej wiadomości działa równolegle i nie wymaga formularza.

## 2. Kiedy używać

| Sytuacja w produkcie                        | Źródło                 |
| ------------------------------------------- | ---------------------- |
| Ekran `/login`                              | US-01, S-01 AC-1, AC-4 |
| Powrót po wygasłym linku lub wygasłej sesji | S-01 AC-3b, AC-6b      |
| Otwarcie zaproszenia bez zalogowania        | US-08                  |

## 3. Kiedy nie używać

| Sytuacja                   | Zamiast                       | Źródło                                  |
| -------------------------- | ----------------------------- | --------------------------------------- |
| Zmiana nazwy wyświetlanej  | formularz (wzorzec Formularz) | US-24                                   |
| Logowanie hasłem lub OAuth | brak w MVP                    | PRD, AGENTS.md (rozstrzygnięte decyzje) |

## 4. Anatomia

| Część                       | Opcjonalna | Uwagi                                                         |
| --------------------------- | ---------- | ------------------------------------------------------------- |
| Komunikat powodu (`notice`) | tak        | `Alert` nad formularzem                                       |
| Krok 1: „Adres e-mail”      | nie        | `type="email"`, `autocomplete="email"`, „Wyślij kod”          |
| Krok 2: „Kod z wiadomości”  | nie        | `inputmode="numeric"`, `autocomplete="one-time-code"`, 6 cyfr |
| „Wyślij nowy kod”           | nie        | bez ponownego wpisywania adresu                               |
| „Zmień adres e-mail”        | nie        | powrót do kroku 1 z zachowanym adresem                        |

## 5. Warianty

Jeden formularz; różni się tylko komunikatem powodu: wygasły link, wygasła sesja, zaproszenie.

## 7. Zachowanie i dostępność

## 10. API

| Prop          | Typ                                                              | Opis                                     |
| ------------- | ---------------------------------------------------------------- | ---------------------------------------- |
| `requestCode` | `(email: string) => Promise<SubmitResult<"email">>`              | `signInWithOtp`; błędy Auth → komunikaty |
| `verifyCode`  | `(email: string, code: string) => Promise<SubmitResult<"code">>` | `verifyOtp`                              |
| `onSignedIn`  | `() => void`                                                     | przejście na adres powrotu               |
| `notice`      | `string`                                                         | powód wejścia na ekran                   |

## 11. Kod

```tsx
<SignInForm
  notice={
    search.error_code === "otp_expired"
      ? "Link wygasł lub został już użyty. Wyślij nową wiadomość."
      : undefined
  }
  requestCode={async (email) => {
    const { error } = await supabase.auth.signInWithOtp({
      email,
      options: { emailRedirectTo: `${origin}/login` },
    });
    return error ? { ok: false, formError: toAppError(error).message } : { ok: true };
  }}
  verifyCode={async (email, token) => {
    const { error } = await supabase.auth.verifyOtp({ email, token, type: "email" });
    return error ? { ok: false, fieldErrors: { code: toAppError(error).message } } : { ok: true };
  }}
  onSignedIn={() => navigate({ to: search.redirect })}
/>
```

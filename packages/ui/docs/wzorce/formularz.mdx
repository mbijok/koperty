# Formularz

`import { useFormSubmit } from "@koperty/ui/patterns/use-form-submit";`
Przykład referencyjny: `import { IncomeForm } from "@koperty/ui/views/funds/income-form";`

## 1. Do czego służy

Zapisuje dane przez funkcję RPC tak, żeby osoba nigdy nie straciła tego, co wpisała, i wiedziała, czy zapis się udał. Hak `useFormSubmit` realizuje zachowanie, a `IncomeForm` (przychód, US-14) pokazuje je na prawdziwym formularzu.

## 2. Kiedy używać

| Sytuacja w produkcie                                          | Źródło              |
| ------------------------------------------------------------- | ------------------- |
| Każdy formularz zapisujący dane: przychód, przydział, wydatek | US-14, US-16, US-17 |
| Profil, nazwa budżetu, nazwa koperty                          | US-24, US-04, US-11 |

## 3. Kiedy nie używać

| Sytuacja                                    | Zamiast                               | Źródło           |
| ------------------------------------------- | ------------------------------------- | ---------------- |
| Pojedyncza akcja bez pól (usuń, archiwizuj) | potwierdzenie usunięcia albo przycisk | polecenie budowy |
| Przełącznik zapisujący od razu              | przełącznik (zmiana działa od razu)   | WCAG 3.2.2       |

## 4. Anatomia

| Część                      | Opcjonalna | Uwagi                                                       |
| -------------------------- | ---------- | ----------------------------------------------------------- |
| Pola (`FormField`)         | nie        | etykieta zawsze widoczna, podpowiedź, komunikat błędu       |
| Komunikat błędu formularza | tak        | `Alert` `danger` nad przyciskami, gdy błąd nie dotyczy pola |
| Przycisk główny            | nie        | czasownik i obiekt („Zapisz przychód”), stan oczekiwania    |
| „Anuluj”                   | tak        | przycisk drugorzędny; przy edycji                           |

## 5. Warianty

Nowy obiekt (pusty formularz, data dzisiejsza) i edycja (`initial`, `submitLabel="Zapisz zmiany"`, „Anuluj”). Zachowanie jest to samo.

## 7. Zachowanie i dostępność

| Zasada                                                                                                        | Źródło                       |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| Walidacja pola po jego opuszczeniu i całości przy wysłaniu; nigdy w trakcie pisania.                          | polecenie budowy             |
| Po nieudanym wysłaniu fokus trafia na pierwsze pole z błędem (`[aria-invalid="true"]`).                       | polecenie budowy, WCAG 3.3.1 |
| Błąd jest powiązany z polem przez `aria-describedby` (`FormField`).                                           | WCAG 3.3.1, 1.3.1            |
| Wpisane dane zostają przy każdym błędzie; formularz nie czyści pól.                                           | polecenie budowy             |
| Blokada podwójnego wysłania: przycisk w stanie oczekiwania ignoruje kliknięcia, hak ignoruje drugie `submit`. | polecenie budowy             |
| Sukces dopiero po potwierdzeniu z serwera; bez optymistycznego „Zapisano”.                                    | polecenie budowy             |
| Walidacja w przeglądarce tylko pomaga; reguły egzekwuje baza, a jej kody błędów mapuje `submit`.              | AGENTS.md, ADR 0003          |
| Brak sieci rozpoznawany przez `navigator.onLine` po nieudanym wywołaniu.                                      | propozycja (E3-P7)           |

## 10. API

| Element                                           | Typ                                                               | Opis                                      |
| ------------------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------- |
| `useFormSubmit({ validate, submit, onSuccess })`  | –                                                                 | hak wzorca                                |
| `validate`                                        | `() => FieldErrors<F>`                                            | błędy pól; pusty wynik = poprawne         |
| `submit`                                          | `() => Promise<SubmitResult<F>>`                                  | wywołanie RPC; wyjątek = sieć albo serwer |
| zwraca                                            | `{ fieldErrors, formError, submitting, validateField, onSubmit }` | stan i obsługa zdarzeń                    |
| `IncomeForm` `initial`, `submitLabel`, `onCancel` | –                                                                 | edycja                                    |

## 11. Kod

Nowy formularz z wzorca (kody błędów: `docs/architecture.md`, sekcja „Kontrakt błędów”):

```tsx
const form = useFormSubmit<"name">({
  validate: () => ({ name: name.trim() ? undefined : "Podaj nazwę koperty." }),
  submit: async () => {
    const { error } = await supabase.rpc("create_envelope", { p_budget_id: budgetId, p_name: name });
    if (!error) return { ok: true };
    if (error.message === "ENVELOPE_NAME_TAKEN") {
      return { ok: false, fieldErrors: { name: "Masz już kopertę o tej nazwie." } };
    }
    throw error;
  },
  onSuccess: () => navigate({ to: "/envelopes" }),
});

<form noValidate onSubmit={form.onSubmit}>
  <FormField label="Nazwa" error={form.fieldErrors.name}>
    {(control) => <Input {...control} value={name} onChange={…} onBlur={() => form.validateField("name")} />}
  </FormField>
  {form.formError && <Alert variant="danger"><AlertTitle>{form.formError}</AlertTitle></Alert>}
  <Button type="submit" loading={form.submitting} loadingText="Zapisywanie…">Dodaj kopertę</Button>
</form>
```

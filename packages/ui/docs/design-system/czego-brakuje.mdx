# Czego brakuje

Dwie tabele: pokrycie backlogu MVP (co jest gotowe w design systemie dla każdego zadania) i elementy, których system świadomie nie ma. Priorytet to kolejność z zgłoszenia zbiorczego „Backlog MVP” (#20, `docs/backlog.md`).

„Gotowe” znaczy: komponenty, wzorce i ekrany są w Storybooku ze stanami i testami. Każde zadanie nadal wymaga pracy w produkcie: migracji, RLS, RPC, testów pgTAP, tras, zapytań TanStack Query i podpięcia widoków (vertical slice, `docs/backlog.md`).

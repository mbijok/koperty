# Wsteczna zgodność

Chronione powierzchnie kontraktu tego repozytorium i wymagana ścieżka ich zmiany. Szczegóły w [docs/architecture.md, sekcja 5](docs/architecture.md#5-wersjonowanie-i-wsteczna-zgodność-api). Backend (Supabase) obsługuje aplikację webową i przyszłą aplikację iOS; starsze wersje klienta iOS mogą działać miesiącami po wydaniu nowej, więc kontrakt bazy musi zostawać zgodny wstecz.

Skille przeglądu sprawdzają zmiany względem tego pliku, a skille implementacji ostrzegają, gdy zmiana go narusza. Zmiana łamiąca wymaga ADR w `docs/adr/` i planu migracji, zatwierdzonych przed implementacją.

## Powierzchnie

| Powierzchnia                            | Gdzie                                                | Zmiana łamiąca                                                                                                                                                 | Wymagana ścieżka                                                                                                                                   |
| --------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tabele i kolumny czytane przez klientów | `supabase/migrations/` (schemat `public`)            | zmiana nazwy lub typu kolumny, usunięcie tabeli lub kolumny, nowa kolumna `not null` bez wartości domyślnej, zawężenie polityki `select` widocznej dla klienta | tylko zmiany addytywne; usunięcie po okresie wycofania z ADR i planem migracji                                                                     |
| Funkcje RPC                             | `supabase/migrations/`                               | zmiana nazwy, parametrów, typów lub znaczenia wyniku; nowy parametr bez wartości domyślnej; usunięcie funkcji                                                  | nowa funkcja z sufiksem wersji (np. `create_expense_v2`), stara działa dalej; wycofanie przez `comment on function ... is 'DEPRECATED: ...'` i ADR |
| Kody błędów biznesowych                 | katalog w `docs/architecture.md` („Kontrakt błędów”) | zmiana lub usunięcie kodu, zmiana jego SQLSTATE `PTxyz` / statusu HTTP                                                                                         | nowe kody tylko dopisywane do katalogu                                                                                                             |
| Edge Functions                          | `supabase/functions/`                                | zmiana nazwy, wejścia, wyniku lub reguł (np. `delete-account`)                                                                                                 | nowa wersja obok starej; wycofanie z ADR                                                                                                           |
| Zastosowane migracje                    | `supabase/migrations/`                               | jakakolwiek edycja pliku już zastosowanego                                                                                                                     | zawsze nowa migracja                                                                                                                               |
| Typy klienta                            | `apps/web/src/lib/database.types.ts`                 | ręczna edycja, typy rozjechane ze schematem                                                                                                                    | generowane na nowo po każdej migracji (`vp exec supabase gen types typescript --local`)                                                            |
| Format danych                           | kwoty `bigint` w groszach, daty operacji `date`      | zmiana jednostki lub typu (np. złotówki, `numeric`, `timestamptz`)                                                                                             | wymaga ADR (por. ADR 0004)                                                                                                                         |
| Adresy aplikacji webowej                | `apps/web/src/routes/`                               | usunięcie lub zmiana ścieżki, do której prowadzą linki zewnętrzne (magic link, zaproszenia)                                                                    | przekierowanie ze starej ścieżki                                                                                                                   |
| Format `.ai/`                           | `scripts/check-ai.ts`, `AGENTS.md`                   | zmiana nazewnictwa plików lub statusów bez aktualizacji kontroli i istniejących plików                                                                         | zmiana w `AGENTS.md` i `check-ai.ts` w jednym PR                                                                                                   |

## Dozwolone bez dodatkowej ścieżki

Nowe tabele, nowe kolumny nullable lub z wartością domyślną, nowe funkcje, nowe opcjonalne parametry z wartością domyślną, nowe kody błędów, nowe trasy.
